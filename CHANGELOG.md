# Changelog

All notable changes to **IndraMQTT** ([indramqtt.com](https://indramqtt.com)) are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

---

## [Unreleased] - Sprint 20

### Security
- **libz-sys 1.1.31 → 1.1.33**: fixes advisory RUSTSEC-2026-0544, where gz_vacate() has a heap buffer overflow.
- **libz-sys 1.1.29 → 1.1.31**: fixes advisory RUSTSEC-2026-0418, where the build script leaked the build environment.
- **aws-smithy-http 0.64.0 → 0.64.3, aws-smithy-runtime 1.15.0 → 1.16.2, aws-smithy-types 1.8.0 → 1.9.1, aws-smithy-async 1.3.0 → 1.3.1**: removes the unmaintained `pin-utils` dependency and fixes advisory RUSTSEC-2026-0441.

### Removed
- **Unused hand-written transports**: removed `TcpAlloydbTransport`, `TcpCockroachDbTransport`, `TcpKafkaTransport`, `TcpConfluentTransport`, `TcpMySqlTransport`, `TcpRedisTransport`, `TcpRabbitTransport`, `TcpMqttBridgeTransport`, `TcpTimescaleTransport`, `TcpPulsarTransport`, `TcpOpcUaTransport`, `TcpGcpIotTransport`, `TcpPgTransport`, `HttpBigQueryTransport`, `HttpDynamoDbTransport`, `HttpElasticsearchTransport`, `HttpGcpPubSubTransport`, `HttpKinesisTransport`, `HttpRedshiftTransport` and `HttpS3Transport`. No production path reached them. The maintained vendor drivers remain the production transports.

### Added
- **Connector lifecycle (MV-06b)**: `POST /api/v5/connectors/{id}/{operation}` serves `start`, `stop` and `restart`. Each keeps the stored settings and answers 204. `restart` runs a fresh connection test and enables the connector. `status` and `status_reason` come from the sink state. The schema listing names exactly the ready capability kinds. See [`docs/connectors/`](docs/connectors/index.md).
- **Rules API parity (MV-06a)**:
  - The `FROM` clause of a rule is read with the rule SQL parser. Several sources, quoted topic filters and event sources route correctly.
  - An absent or invalid `FROM` answers `400 BAD_REQUEST` and names the problem.
  - `POST /api/v5/rules` stores and returns `description` and `metadata`.
  - `PUT /api/v5/rules/{id}` merges the body fields into the stored rule.
  - `GET /api/v5/rules` accepts the documented filters.
  - `GET /api/v5/rules/{id}/metrics` adds `failed.no_result` and `node_metrics`. The reset route zeroes every counter.
  - `POST /api/v5/rule_test` requires `event_type` in a non-empty context. It answers `412 NOT_MATCH` when no topic matches.
  - See [`docs/rules/`](docs/rules/index.md).
- **HTTP, device and local kinds (MV-03c)**: add `http`, `opc_ua`, `sparkplug_b` runtimes with aliases. Missing fields answer 400. See [`docs/connectors/`](docs/connectors/index.md).
- **Message-broker connectors are ready**: the `kafka`, `confluent`, `rabbitmq`, `pulsar`, `rocketmq`, `mqtt_bridge` and `redis` kinds now own action runtimes. The aliases `kafka_producer`, `kafka_consumer`, `confluent_producer`, `confluent_kafka`, `confluent_cloud`, `rabbit`, `amqp`, `mqtt`, `mqtt-bridge` and `bridge` select the same runtimes. The connector carries the connection only; the action carries the target (topic, key, headers, strategy, exchange, routing key, command). A missing required field answers 400 and names the field. A broker ack or a send receipt is checked for every delivery; a refused ack counts one failed forward. Each kind proves delivery, update, refused update, recovery and failure counting through the broker against a loopback fake. The bridge remaps topics so a bridged message is never bridged back. Live delivery against real servers waits for the CTO release run. See [`docs/connectors/`](docs/connectors/index.md).
- **Document and search connectors are ready**: the `mongodb`, `couchbase` and `elasticsearch` kinds now own action runtimes with required fields, action-selected collections, indexes, ids and document templates. The aliases `mongo`, `documentdb`, `couch`, `cb`, `elastic` and `es` select the same runtimes. A document template that does not render a JSON object counts one failed forward. The connector, action, probe and schema endpoints accept the documented fields.
- **Time-series and analytics connectors (MV-02b)**: the ten kinds `clickhouse`, `tdengine`, `greptimedb`, `iotdb`, `opentsdb`, `doris`, `datalayers`, `influxdb`, `timestream` and `cassandra` are ready. The aliases `aws_timestream`, `scylla`, `scylladb`, `cql` and `opents` select the same runtimes. Each connector carries the full target. Each action may override its target. A missing required field answers 400 and names the field. Nine kinds prove delivery through the broker against loopback fakes. Cassandra proves failure counting and state through the broker. Live delivery against real servers waits for the CTO release run. See [`docs/connectors/`](docs/connectors/index.md).
- **Object, file and cloud connectors (MV-02d)**: the seven kinds `s3`, `azure_blob`, `dynamodb`, `bigquery`, `disk_log`, `snowflake` and `tablestore` are ready. The aliases `minio`, `azure_blob_storage`, `dynamo`, `ddb`, `bq`, `gbq`, `snowflake_streaming`, `snowflake_aggregated` and `ots` select the same runtimes. A connector holds the connection. An action holds the bucket, key, container, blob, table, dataset, file path, pipe or table name. A missing required field answers 400 and names the field. `disk_log` refuses an absolute path and a `..` component. `databricks` and `delta_lake` are refused under D3 because the reference does not define them. See [`docs/connectors/`](docs/connectors/index.md).
- **Cloud messaging connectors (MV-03b)**: the three kinds `kinesis`, `gcp_pubsub` and `azure_eventhubs` are ready. The aliases `aws_kinesis`, `gcp`, `pubsub`, `azure`, `eventhubs` and `azure_event_hub_producer` select the same runtimes. A connector holds the connection and credentials. An action holds the stream, topic or hub. A missing required field answers 400 and names the field. The three IoT kinds `aws_iot`, `azure_iot` and `oci_streaming` are pending: the reference 6.3.0 has no schema, and the CEO kept them out of the MVP on 2026-11-08. Their create and update answer `400 BAD_REQUEST`. `gcp_iot` and its aliases are refused under D3 because the vendor closed IoT Core. Live delivery against real servers waits for the CTO release run. See [`docs/connectors/`](docs/connectors/index.md).
- **Tenant isolation of shared, will, reconnect and cluster**: a shared group balances inside each tenant only. A will fires inside its own tenant only. A reconnect in another tenant starts a fresh session and never takes over. A cluster seed or enabled flag is refused at boot. The broker fails boot with the reason. It binds no cluster socket and forwards no message. See `docs/multi-tenancy/index.md`.
- **Authentication chain deny and cache**: a known local name with a wrong password denies at once with 0x86. The denial stops the chain and never falls through to a later backend. An unknown local name ignores to the next enabled backend. A stored non-empty chain decides in its own order with its own enable flags. Each chain change and each user create, password change, removal or import evicts the node authentication cache for the affected names. A namespace config with an external backend key (`auth`, `authentication`, `ldap`, `kerberos`, `jwks`, `dbauth`, `webhook`) is refused with 400 and stores nothing, also on both bulk import paths. A non-default tenant cannot use a global external backend. The CONNECT is denied and logged. See `docs/security/authentication.md`.
- **MQTT listeners of the kernel**: with `listeners.tcp.native = true` or `listeners.tls.native = true`, the kernel accepts the MQTT clients of that listener itself, without the edge process in the data path. The default is `false`. The kernel listener handles MQTT 3.1.1 and MQTT 5, applies `listeners.tcp.max_connections`, limits a CONNECT packet to 64 KiB and other packets to 1 MiB, and closes a client that does not read for 30 seconds. UNSUBSCRIBE, WebSocket and PSK are not available on this listener yet.
- **Broker comparison**: [`benchmark/`](benchmark/README.md) contains the method, the tool and the raw results of the comparison at 1 CPU and 1 GB.
- **Amazon Kinesis Sink (`INDRA-197`)**: High-throughput `PutRecords` batch ingestion with SigV4 signing, dynamic partition key derivation, and partial-failure exponential retry.
- **Google Cloud Pub/Sub Sink (`INDRA-199`)**: `v1.publisher.publish` batch sink with ordering keys, dynamic attributes, and OAuth2/JWT authentication.
- **Azure Event Hubs Sink (`INDRA-198`)**: Batch event ingestion with Shared Access Signature (SAS) token generation and partition key hashing.
- **Apache Pulsar Producer Sink (`INDRA-153`)**: Multi-tenant (`tenant/namespace/topic`) partitioned producer with keyed routing and sequence tracking.
- **Cloud Streaming Studio (`INDRA-218`)**: REST API and Web Dashboard forms for all 4 cloud bridges.
- **Oracle error kinds**: the Oracle sink maps each driver error by its typed code to connection, authentication, constraint, syntax, timeout, transport or unknown. Connection, timeout and transport retry. The rest stop at once. `ORA-00000` retries, and a code that does not parse stops.

- **Action resource options and counters**: an `http`, `webhook` or `pgsql` action applies `batch_size`, `batch_time`, `inflight_window`, `max_buffer_bytes`, `request_ttl`, `query_mode`, `worker_pool_size` and `health_check_interval` from `resource_opts`. The runtime runs a periodic target health check and reports a failed check as `disconnected` with the reason. A non-default value that it cannot apply is refused with 400 and the field name. `GET /api/v5/actions/{id}/metrics` reports `total`, `matched`, `success`, `failed`, `dropped` with reasons, `queuing` and `inflight`; the reset route zeroes every counter. See [`docs/rules/actions.md`](docs/rules/actions.md).
- **Actions API and action limits (MV-07)**: the broker holds at most 1024 actions. A create past the cap answers 400. A stored list above the cap still boots with all rows, raises `action_limit_exceeded`, and refuses new rows. A delete of a linked action answers 400 with the `rules` array. Each `GET /api/v5/actions_summary` row carries `name`, `type`, `enable`, `status`, `node_status`, and `rules`. See [`docs/rules/actions.md`](docs/rules/actions.md).
- **Source ingress (MV-08)**: an MQTT source connects through its `mqtt` connector, subscribes to the configured remote topic, and publishes each remote message into the local broker. A source update or delete stops the old consumer before a new one starts, so one remote message has one local delivery. The source read reports the live `status`, and `status_reason` when disconnected. A reference source kind without an ingress runtime answers 400 at create and update and stays out of `GET /source_types`. The `POST /sources_probe` path refuses such a kind and dials a supplied target. See [`docs/reference/sources.md`](docs/reference/sources.md).
- **Relational database actions (`mysql`, `mssql`, `oracle`, `alloydb`, `cockroachdb`, `redshift`)**: each action owns its sink, built from the referenced connector document (connection fields only) plus the action's `parameters.sql`. Values bind as parameters, never as text. `?` marks MySQL. `$1` to `$5` mark SQL Server. `:1` to `:3` mark Oracle. `$1` to `$3` mark the PostgreSQL-protocol kinds. A missing field is refused with 400 and names the field. An unsupported option is refused instead of ignored. A dead server counts each fire as failed. Oracle delivery against a live server is proved by the release qualification run. See the connector pages under [`docs/connectors/`](docs/connectors/index.md).
- **Built-in rule actions of the reference API**: a rule accepts the actions that `POST /api/v5/rules` and `PUT /api/v5/rules/{id}` document. An item of `actions` is the id of a stored action, `{"function": "console"}`, or `{"function": "republish", "args": {...}}`. The arguments are `topic`, `payload` (default `${payload}`), `qos` (default `${qos}`), `retain` (default `${retain}`), `mqtt_properties`, `user_properties` and `direct_dispatch`. A value with `${...}` is a template. `${field}` and `${a.b}` take a field of the rule result, `${payload}` is the result row (for `SELECT *`, the input payload), and `${topic}`, `${qos}` and `${retain}` fall back to the input message. A missing variable gives `undefined` in `payload`, and an error in `topic`. The republished message stays in the tenant of the rule and does not start a rule again. A retained republish is stored with the same limits as a retained publish. `mqtt_properties` supports `Payload-Format-Indicator` and `Message-Expiry-Interval`; `user_properties` takes one reference to a map. `Content-Type`, `Correlation-Data` and `Response-Topic` give 400, because the publish path cannot carry them. `direct_dispatch` true clears the retain flag. A function in the `module:function` form gives 400, because this broker cannot load user code. The read routes return the actions in the documented shape (a string for a stored action). `console` writes the result row to the log at info level on one line, at most 1024 bytes.
- **Rule test**: `POST /api/v5/rules/{id}/test` accepts `stop_action_after_template_rendering` and refuses `false`, because the test does not run actions.
- **Template scanner**: `render_template_with` in `broker-connectors` takes any variable source. `render_template` keeps multi-byte text in the literal part of a template.
- **Dashboard user scopes**: `POST /users`, `PUT /users/{username}` and `GET /users` carry the `scopes` field. An omitted field on create stores the role default. The value `unset`, and a list equal to the role default, store no explicit list. An empty list `[]` denies each non-public management route. The public routes stay reachable. Each scope change or role change applies to live tokens on the next request. The login-only scopes are `user_management`, `mfa_management`, `sso_management` and `api_key_management`. The `user_management`, `sso_management` and `api_key_management` scopes need the administrator role. A non-administrator can hold `mfa_management` for their own MFA. Scopes persist across a restart.
- **API keys of the reference API**: `POST /api/v5/api_key` answers 200 with `api_key` (the identifier) and `api_secret` (shown one time). A key authenticates with `Authorization: Basic base64(api_key:api_secret)`, or with the secret as `Authorization: Bearer <api_secret>`. A key has the fields `desc`, `enable`, `expired_at`, `expired`, `role` (`administrator`, `viewer`, `publisher`) and `scopes` (a list or `unset`). A disabled or expired key gets 401, and a `viewer` key can only read. The names follow `^[A-Za-z]+[A-Za-z0-9-_]*$`, 1 to 256 characters. A scope list limits the paths of the key, and a create or an update refuses a scope that is not in `GET /api/v5/api_key_scopes`.
- **Operations for a bearer token only**: a key cannot call `GET`/`POST /api_key`, `GET /api_key_scopes`, `GET`/`POST /users`, `GET /user_scopes` and `POST /logout`, as the reference API lists them. The other operations on users, single sign-on and one API key accept an `administrator` key without a scope list. A namespace on a key gives `BAD_REQUEST` because this broker has no namespaces.
- **Licence endpoints of the reference API**: `GET/POST /api/v5/license`, `GET/PUT /api/v5/license/setting` and `GET /api/v5/license/session_hwm_history`. The broker is open source: the licence document is fixed, it does not expire, and its limits are 10,000,000,000. The broker applies no limit from it. The session history is the highest number of connected sessions for each day, kept for 24 months.
- **MFA at login**: a user with MFA must send the code as `mfa_token` in the login request. Without the code, or with an incorrect code, the answer is 401 with the code `BAD_MFA_TOKEN`. A viewer can enrol MFA for that viewer.
- **Login lockout**: five incorrect passwords in sequence lock the user for 60 seconds. The answer is 401 with the code `LOGIN_LOCKED`.
- **Login error code**: an incorrect user name or password gets the code `BAD_USERNAME_OR_PWD`. Before this change the code was `NAME_PWD_ERROR`.
- **Agent protocol endpoint**: `POST /mcp` on the management listener serves the methods `initialize`, `ping`, `tools/list` and `tools/call` as JSON-RPC 2.0 over plain HTTP responses. The endpoint authenticates an API key (Basic or Bearer) through the same code path as the management API; a user login token is refused, and a missing key gets HTTP 401 with a plain error object. Each tool runs one management operation through the live router with the same key scopes and viewer rule as HTTP, plus the built-in `broker_status` and the always-present `list_toolsets`. The tools form 17 toolsets selected with `?toolsets=a,b` (default `core`, `all` for every tool). The `publish` toolset also holds `subscribe_collect`, which subscribes briefly and collects matching messages of the default tenant. A viewer key sees read tools only, `mcp.read_only = true` keeps read tools only for every key, and each call writes one audit record naming the key, the tool and the result, never the arguments. New settings `mcp.enabled` (default `true`, off answers 404) and `mcp.read_only` (default `false`). See `docs/mcp.md`.
- **Rule functions refused at creation**: rule creation, rule update, the rule tester and file load answer 400 for a rule whose SQL statically calls a function the broker never serves. The message names the function, the hash algorithm or the time zone. Refused calls are `schema_encode` and `schema_decode`, `hash` with a `sha3` or `blake2` algorithm, and a named time zone (outside `Z`, `UTC` and fixed offsets) in `timezone_to_second`, `timezone_to_offset_seconds` or four-argument `date_to_unix_ts`. A refused update keeps the live rule working. A dynamic (non-literal) value still creates and fails closed at execution.
- **jq timeout applied**: `jq` with three arguments applies the third as a budget in milliseconds (1 to 3600000, default 10000). A program past the deadline or past 64 path segments stops, returns null and counts one stopped run. The rule that asked for the value does not match, so its failed counter moves.

### Changed
- **Connector, action and source kinds that are not ready are refused**: a create, update or probe of a kind that is not `ready` answers `400`. The refusal message is `connector type <kind> is not available in this broker`. Nothing is stored. A refused update keeps the old record. A strict file load fails and names the file, key and kind. A stored record from an earlier version stays visible and deletable. It reports `disconnected` with a `status_reason`. It raises `connector_unavailable:<id>` or `action_unavailable:<id>`. A rule that uses it stays enabled and counts a failed forward. The schema, action-type and source-type listings show only ready kinds. At the close of KC-00 only `pgsql`, `webhook`, `console` and `logger` are ready. These formerly working kinds are now pending their family ticket. They are `alloydb`, `aws_iot`, `azure_blob`, `azure_eventhubs`, `azure_iot`, `bigquery`, `cassandra`, `clickhouse`, `cockroachdb` and `confluent`. They also include `couchbase`, `databricks`, `datalayers`, `disk_log`, `doris`, `dynamodb`, `elasticsearch`, `gcp_iot`, `gcp_pubsub` and `greptimedb`. The remaining pending kinds are `http`, `influxdb`, `iotdb`, `kafka`, `kinesis`, `mongodb`, `mqtt_bridge`, `mssql`, `mysql` and `oci_streaming`. The last group is `opc_ua`, `opentsdb`, `oracle`, `pulsar`, `rabbitmq`, `redis`, `redshift` and `rocketmq`. The final kinds are `s3`, `snowflake`, `sparkplug_b`, `tablestore`, `tdengine`, `timescaledb` and `timestream`. The v1 `/api/v1/connectors` path and SQL `INTO connector("id")` keep their old delivery.
- **Action and connector generations**: one connector or action write now builds the new sinks before it persists them. A persist failure keeps the old store and the old sinks. A swap drains the old action buffer, so a batch is not lost. The connector update rebuilds only its dependent actions. A pgsql action reads TLS and password references from its connector, and sends the password and database as values. A down target reports `disconnected` from a real connection attempt; the v1 path keeps its own memory name space.
- **Connector, action and source probe status codes**: `POST /connectors_probe`, `POST /actions_probe` and `POST /sources_probe` answer 204 with no body on success, and 400 `TEST_FAILED` on every failure. `POST /connectors`, `POST /actions` and `POST /sources` answer 400 `ALREADY_EXISTS` for an unknown or removed kind. Before this change the probes answered 200 with a body and the failures used 400 `BAD_REQUEST`.
- **S3 Tables connector removed**: new connectors, actions and sources of type `s3_tables`, `s3tables` or `iceberg` get `400` with `connector type s3_tables is not available in this broker`; nothing is stored. An existing `state.toml` still starts. The broker keeps the stored records readable and deletable, reports them as `disconnected` with a `status_reason`, and raises `connector_unavailable:<id>` or `action_unavailable:<id>`. Rules stay enabled: a forward to the removed connector counts a failed action and other actions keep working. Delete the rule, then the action, then the connector.
- **Rule result order**: JSON results keep SELECT or DO order, including aliases, wildcard input order and nested objects. Rule updates and restarts keep that order. Republish, console, connector forwarding and the rule tester share the ordered row. Whole-row table sinks keep columns paired with values in projection order. Repeated output names keep their first position and take the last value in ordinary and window projections.
- **JSON objects**: all builds retain insertion order. Management responses keep the order in which their code inserts members; object members are no longer sorted by default.
- **One Rust process**: the kernel serves every enabled MQTT listener for TCP, TLS, WebSocket and secure WebSocket. The image runs one process and starts no edge process. The documents describe this path. When the kernel stops, it closes the client sockets and clients connect again.
- **Packet size limit**: `session.max_packet_size` sets the largest MQTT packet in bytes. The default is 1048576. It sets the TCP and TLS read limit and the WebSocket frame cap. The kernel advertises it in CONNACK. A larger v5 packet gets DISCONNECT 0x95.
- **Offline queue bound**: `session.max_offline_queue` sets the live per-session offline cap at boot. The default is 50000. Past the cap the oldest entry drops and `indramqtt_offline_queue_evicted_total` counts it. A kept zone value still wins when set. The backlog survives a restart on the same data dir. Before this change the file value loaded but the broker kept its built-in cap.
- **`node.brokerlink_bind`**: the setting and the flag `--brokerlink-bind` are deprecated and ignored. Files and variables that set them still load, and the kernel logs a warning. A later release removes them.
- **MQTT listeners of the kernel**: the kernel serves every enabled MQTT listener. The four `native` settings are deprecated and ignored. Files and variables that set them still load, and the kernel logs a warning for each one that a layer sets. A value of `native = false` requests the removed edge, so its warning is stronger. A stale entrypoint that still starts the edge opens no client socket.
- **Licence**: all the code in this repository is now under MIT OR Apache-2.0. The enterprise licence file and the licensing guide are removed. The crates `broker-cluster`, `broker-connectors-enterprise` and `broker-rules-enterprise` use the licence of the workspace. The licence functions in the code (trial period, licence key, tier names) stay for now. They are removed step by step before the stable release.
- **README**: the README is written again in Simplified Technical English. It has the roadmap to the stable release.
- **Direction**: the Erlang edge is deprecated. The kernel serves all MQTT listeners and the image runs one process. A later release removes the remaining edge files.
- **Release profile**: a panic now unwinds. A panic in the task of one connection ends only that connection, and the kernel releases its session. Before this change, one panic stopped the broker.
- **Subscription statistics**: the count of subscriptions and topics runs when a statistic is read. Before this change, it ran for each connect, subscribe and disconnect, and the work increased with the square of the number of connections. A maximum can miss a peak that is between two reads.
- **Kafka connector `health_check_topic` default**: the schema default is now `indramqtt_health_check`. Anyone who set the topic explicitly is unaffected; to keep the previous topic, set `health_check_topic` explicitly in the connector configuration.
- **Node information**: `GET /api/v5/nodes` and `GET /api/v5/nodes/{node}` report real values. `version` is the version of the build. `otp_release` is the Rust compiler release and the target of the build. `uptime`, `memory_used`, `memory_total`, `load1`, `load5`, `load15`, `max_fds`, `process_used`, `cluster_sessions` and `sys_path` come from the running process and the operating system. A field that has no true value is left out. Before this change the endpoints returned fixed example values.
- **Success status codes**: these operations now answer the status that the reference API documents. They answer 204 with no body: the `enable` and `start`/`stop` operations of actions, connectors and sources (also per node), `POST /sources_probe`, `PUT /authentication/{id}`, `PUT /authentication/{id}/position/{position}`, `POST /authorization/sources`, `PUT /authorization/sources/{type}`, `POST /authorization/sources/{type}/move`, the built-in rule creation for clients and users, `POST /clients/kickout/bulk`, `POST /users/{username}/mfa`, `POST /data/import` and the enable operation of a message transformation. `POST /authentication` answers 200. `GET /clients/{clientid}` answers the code `CLIENTID_NOT_FOUND` for an unknown client. The secret of a new MFA enrolment is available from `POST /sso/mfa/setup`.
- **Status endpoint**: `GET /api/v5/status` needs no authentication, and `GET /status` is an alias. The plain text answer is two lines: `Node <node name> is started` and `indramqtt is running`. With `?format=json` the answer has `rel_vsn`, `node_name`, `broker_status` and `app_status`. `indra status` reads the JSON form.
- **List bodies**: `GET /actions`, `/actions_summary`, `/authentication`, `/connectors`, `/error_codes`, `/schema_registry`, `/sources`, `/sources_summary` and `/users` answer a bare JSON array, as the reference API documents. They do not take paging parameters. Before this change they answered an object with `data` and `meta`, and the two summaries answered counts. A summary row has `name`, `type` and `enable`. A user row has `backend` and `mfa`. `GET /topics/{topic}` answers an array with one row per node, and the 404 code is `TOPIC_NOT_FOUND`. `PUT /message_transformations` takes one transformation object and answers the stored object (404 `NOT_FOUND` for an unknown name); an array body still replaces the whole chain.
- **User error codes**: an unknown dashboard user answers 404 `USER_NOT_FOUND`. A wrong old password in a password change answers 400 `ERROR_PWD_NOT_MATCH`. Removing or demoting the last administrator answers 400 `NOT_ALLOWED`. `DELETE /users/{username}/mfa` for a user without MFA answers 204.
- **Features**: `GET /features` answers `preset`, `enabled` and `disabled`, as the reference API documents. The two lists name the features of the management console that this build provides and does not provide. The management console hides the pages of the disabled features.
- **Monitor current**: `GET /monitor_current` and `GET /monitor_current/nodes/{node}` answer the fields that the reference API documents, with the `*_rate` fields. A rate is the change of a counter between the two newest monitor points, divided by the time between them. The route `GET /monitor_current/nodes/{node}` adds `node_uptime`, in seconds. The fields `license_quota`, `shared_subscriptions` and `sessions_hist_hwmark` are left out because the broker keeps no such value.
- **Listeners**: `GET /listeners` answers one row for each MQTT listener with `id`, `name`, `type`, `bind` and `enable`. The type of the TLS listener is `ssl`. The HTTP listener of the management API has no row. The query `type` narrows the list. `indra listeners` shows the new fields. The start, stop and edit operations of a listener are not done.
- **Session count**: `GET /sessions_count` answers a JSON string with the number of sessions that have not expired, as the reference API documents. It reads the query `since` and no longer reads `node`.
- **Node name**: every endpoint shows the node as `name@host`. The name is the `--node-id` value, and the host is the host name of the machine. A node id with an `@` is used as it is. `/nodes/{node}` accepts the full name and the bare node id. Before this change the endpoints showed the fixed text `indramqtt@127.0.0.1`.
- **Agent protocol endpoint**: the route table behind `POST /mcp` is built one time and shared by every `tools/call`. Authentication and permission checks still run per request against the current stores. A key change, a scope change or a mode change applies to the next call. Each tool description now keeps the handler purpose and names the route after it, for example `List all clients. (GET /api/v5/clients)`. A route without docs still falls back to `METHOD path`. See `docs/mcp.md`.

### Removed
- **Edge flow-control telemetry**: the Prometheus series `indramqtt_credit_clamped_total`, `indramqtt_credit_exhausted_total` and `indramqtt_credit_received_total` are gone. The edge `Credit` frame and its counters go away with the edge path.

### Unstable- **Single sign-on**: the login endpoints of single sign-on answer the error that the reference API documents: 404 `BACKEND_NOT_FOUND` for `POST /sso/login/{backend}` and `POST /sso/saml/acs`, and 400 `BAD_REQUEST` for `GET /sso/oidc/callback` and `POST /sso/token_exchange`. The message says that single sign-on is not available in this release. The flows did not connect to an identity provider. The endpoints that store a backend stay.
- **Deferred functions read honest states**: protocol gateways, message schema validations, OpenTelemetry export and cluster links are not in this release. Each list or config read answers the documented shape with a true empty or disabled state. Each write refuses with the documented 400 code. Nothing is stored. The schema registry itself stays: it stores and serves schemas.

### Security
- **libz-sys advisory RUSTSEC-2026-0418**: the build uses `libz-sys 1.1.31`. This clears the advisory. The build script no longer logs the probe command. The library API and the compression format stay the same.
- **zstd advisory RUSTSEC-2026-0403**: the rule parser uses `zstd 0.14.3` with `zstd-safe 8.2.0`. This clears the advisory. The frame format and the level stay the same.
- **TLS root advisories**: the root data and the certificate verifier move to `webpki-roots 1.0.10` and `rustls-webpki 0.103.16`. This clears RUSTSEC-2026-0381 (the bundled roots carried distrusted emSign intermediates) and RUSTSEC-2026-0382 (the verifier could accept a distrusted intermediate). The trusted roots, the custom CA support and the TLS-off behaviour do not change.
- **Client certificate roots**: a listener with client certificate verification on (`verify = "verify_peer"` or `verify_client_cert = true`) needs `cacertfile`. The configuration check refuses an empty value, and a secure listener does not start without a CA file. The broker no longer uses a built-in set of public authorities for client certificates.
- **Publish without a session**: a PUBLISH from a connection with no bound session is not routed, and the broker closes that connection. After a denial with `deny_action = disconnect`, the broker does not handle the packets that the connection still holds in its read buffer.
- **Delayed publish**: a publish to `$delayed/<seconds>/<topic>` is checked against the access rules, the database rules and the webhook with the target topic, also with the retain flag.
- **Gateway publish**: a CoAP publish is checked against the access rules, the database rules and the webhook in the default tenant, and a denied publish stores nothing and answers 4.01.
- **Certificate key files**: the broker creates key files with mode 0600 at creation, writes to a temporary file in the same directory and renames it over the target. A failed write removes the temporary file. The bundle directory has mode 0700.
- **Publish check cost**: the publish check loads the settings and the source registry without locks, counts verdicts with lock-free counters, and takes no lock for the default tenant with no rules. A non-empty tenant adds one short read lock.
- **Default tenant quotas**: the default tenant has no connection, session or retained limit, and a tenant with no quota setting has none. The listener connection bound still applies. The file defaults for the three per-tenant quotas are now 0 (unlimited). An operator sets a bound explicitly per tenant.
- **Tenant namespaces**: managed namespaces persist through the configuration registry across restarts, with the stored retained caps applied at boot. A failed save rolls the change back. Delete removes the retained messages, the retained cap and the managed entry, so a later tenant with the same name starts empty.
- **PSK handshake**: an unknown identity gets a stand-in key from the per-boot server secret, so it fails with the same alert as a wrong key on TLS 1.2 and TLS 1.3. Session tickets are off, so every handshake runs the lookup. The verified identity is the username of the bind.
- **WebSocket limits**: the upgrade head is limited to 8 KiB with the connect time limit. At most one pong waits for the next flush, and a ping flood with no MQTT byte closes the connection. The library write buffer is 8 KiB.
- **Management stores**: the stores keep serving after a lock failure instead of stopping the process.
- **Authorization settings applied**: `no_match` decides publish, subscribe and will. `deny_action` ignores or disconnects on denial. Disconnect uses the version-correct reason code. `auth.allow_anonymous = false` refuses anonymous CONNECT. Refusal uses 3.1.1 code 5 and 5.0 code 0x87. `auth.password_hash` selects the hash for new credentials (`bcrypt` stores `$2b$`, `sha256` stores 64-char hex). An unsupported value fails the start with an error naming the setting. Old verifiers still verify, and an unreadable verifier never grants access.
- **Authorization cache applied**: the cache policy is enforced on publish, subscribe and will. `enable` selects caching. `max_size` bounds entries per client. `ttl` bounds staleness. `excludes` skips listed topics. Rule, source, user and client changes clear entries.
- **Authorization sources refused**: the broker answers 400 for unevaluated kinds. The error names the kind. Nothing is stored. The old state stays active.
- **Old stored sources deny**: a stored source from an older version stays unchanged. It denies each decision that would reach it. It raises an alarm that names the source. The API keeps read and delete paths open.
- **Failed settings write keeps the old state**: a refused or failed `PUT /authorization/settings` validates before the live value changes. The save precedes the live swap. A failed save leaves the live and the stored decision unchanged.

### Fixed
- **Subscribe cover check**: a narrow allow rule no longer covers a wider request. `a/+` does not cover `a/#`, and `+` does not cover `#`. A deny rule applies when it overlaps the request, so deny `secret/#` denies a subscribe to `#`. A `#` or `+` at the first level no longer matches `$` topics. A subscribe that was allowed before and is denied now is correct here.
- Rule API errors follow the reference API: duplicate rule creation returns `400 BAD_REQUEST`; a stored-rule test for an absent id returns `404 RULE_NOT_FOUND`. A refused duplicate keeps the existing rule and its stored settings.
- **Management API disable flag**: `listeners.api.enabled = false` in `indra.toml` (or `INDRA_LISTENERS__API__ENABLED`) now opens no API socket, while MQTT still serves from the same file. Before this change the broker accepted the flag and kept serving the API.
- **Legacy licence file path**: an explicit non-default `licence.license_file` is refused at load with a native error naming the file and the key. The broker keeps the stored licence and never reads this path. The default path keeps booting unchanged.
- **Node identity at boot**: the kernel fixes the node name from the resolved configuration before any component reads it. `node_status` of a stored connector reports the configured id after a restart instead of the default.
- **Messages that did not arrive in a large fan-out**: the kernel wrote one batch for each wake of a link and then waited. A publish to more subscribers than one batch holds left messages in the queues, and the kernel counted them as delivered. The kernel now writes until the queues are empty.
- **MQTT protocol refusals**: an empty client id without clean start is refused (3.1.1 code 2, v5 code 0x85). A v5 CONNECT with receive maximum 0 closes with no session created. After an accepted CONNECT, a protocol error (second CONNECT, QoS 0 with DUP set, packet id 0, wildcard topic name) closes only that connection, and a v5 client gets DISCONNECT 0x82 first. Reserved SUBSCRIBE option bits and no-local on a shared filter fail only that filter with SUBACK 0x8F.
